claude-code-efficiency

A Claude Code skill for long, expensive sessions — without shell-alias rewriters, analytics, or hidden hooks.

View on GitHub Install

What it does

When your Claude Code session gets long or expensive, this skill loads a structured set of practices that actually reduce token spend — ranked by leverage, with evidence-based recommendations only.

  • Route large tool output through MCP sandboxes or subagents — keep raw data out of the main context window
  • Use Grep-shape + targeted Read instead of full-file reads (native AST skeletonization, zero install footprint)
  • Match permission modes to blast radius — auto-approve only in sandboxes, never over uncommitted work
  • Scope allowlists correctly — project for writes, global only for universal reads
  • Tune effort to problem depth, not to ceremony
  • Clean long sessions with /clear, /compact, and chapter marks
  • Prompt with coordinates, not descriptions — files over inline output
  • Move recurring reminders to CLAUDE.md and harness hooks, not every-turn nudges

Install

cd ~/.claude/skills
git clone https://github.com/scottconverse/claude-code-efficiency.git

Start a new Claude Code session. The skill auto-triggers on phrases like "save tokens," "reduce context," or "be concise" — or invoke it directly via the Skill tool.

How it's built

A single markdown file (SKILL.md) with YAML frontmatter and eight priority sections. No binary. No network access. No dependencies beyond Claude Code itself. Structural tests live in tests/ and verify frontmatter parses, trigger words are present, and forbidden patterns are absent.

Explicitly rejected patterns

This skill does not recommend:

  • Global shell aliases that rewrite git / npm / cargo output
  • Analytics, telemetry, or phone-home behavior in dev tooling
  • --no-verify and other hook bypasses
  • test.skip() and equivalents — skipped tests are lies
  • Marketing "X% savings" numbers without reproducible methodology
  • Trust-by-credential-association ("the guy who built X said so")
